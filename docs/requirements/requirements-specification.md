# AI 热点信息每日汇总系统需求说明书

## 新增需求：首页日期筛选（2026-09-14）

首页公开简报的日期信息需要升级为日历筛选框。用户打开首页时默认查看北京时间当天的已发布 AI 简报；用户选择过去日期后，系统展示该日期已发布的 AI 简报；未来日期不可选；没有对应简报时展示空状态。日期文字需要放大，增强当前日期的识别度。

该需求属于首页用户需求，包含首页日期筛选功能需求和日期文字层级调整的界面需求，不新增业务目标。公开首页通过专用公开接口读取已发布简报；登录保护的 `/history` 页面继续保留。

## 新增需求：自然语言信息库聊天助手（2026-09-08）

网页端在登录后页面提供全局悬浮聊天助手，用户可输入自然语言查询，系统先通过 `LibraryChatIntentClassifier` 判断问题是否属于信息库查询，范围外问题返回固定拒答；范围内问题调用管理员配置的默认启用 LLM Provider + DeepAgents 受限 Agent 理解查询意图，并通过 `search_library_database` 只读工具查询已入库内容。首期支持 SSE 流式状态、回答文本、结果卡片和用户级会话/消息历史落库，不触发外部实时搜索，不允许普通用户借此新增 source、触发采集或访问管理员能力。详见 [自然语言信息库检索需求](../product/natural-language-library-search.md)。

## 新增需求：个人收藏（2026-09-06）

用户可收藏信息库及关注流中的条目，并在“我的收藏”中建立单层目录、重命名、删除目录、移动和取消收藏。没有自建目录时默认存入根目录；有目录时可选择根目录或自建目录。删除目录不删除内容，目录内收藏移回根目录。同一用户不可重复收藏同一条目，收藏与目录为私有数据，管理员无跨用户查看权限。支持按目录搜索、分类/来源筛选、收藏时间/发布时间/分数排序及分页。首期不包括专题收藏、备注、标签或多级目录。详见 [收藏设计](../product/favorites.md)。

## 1. 文档目的

本文档用于明确 AI 热点信息每日汇总系统的业务目标、用户角色、业务流程、功能需求、非功能需求、MVP 边界和验收标准，作为后续架构设计、任务拆分、研发实现和测试验收的依据。

## 2. 业务目标

### 2.1 为什么做这个系统

AI 领域信息更新速度快，来源分散，重复内容多，质量差异大。目标用户每天需要在官方博客、Hacker News、GitHub、arXiv、Product Hunt、Hugging Face、技术媒体和 newsletter 之间反复切换，才能形成当天 AI 动态认知。

本系统希望通过自动采集、标准化、去重、评分、LLM 中文摘要和 Web 看板展示，降低用户获取高质量 AI 热点信息的成本。

### 2.2 业务价值

- 帮助用户在 3-5 分钟内理解当天核心 AI 热点。
- 将分散来源统一到一个 Web 看板。
- 用可解释评分和分类降低信息噪音。
- 用中文摘要降低英文阅读门槛。
- 保留原文链接和 raw payload，确保内容可追溯。
- 支持历史简报回看，形成长期 AI 情报库。

### 2.3 成功指标

- 每天自动生成中文 AI 简报。
- 首期支持 RSS、Hacker News、GitHub、arXiv、Product Hunt、Hugging Face 六类数据源。
- 未登录用户可以查看当天公开简报，登录用户可以查看今日简报、历史简报、条目详情和搜索筛选。
- 管理员可以管理来源、触发采集、查看任务日志和配置 LLM provider。
- 重复 URL 不会在 digest 中重复出现。
- digest 自动发布到 Web 看板，不需要人工审核。

## 3. 用户角色

### 3.1 普通用户

普通用户是 AI 信息消费者，可以在未登录状态查看今日公开简报，登录后查看系统生成的完整内容。

权限：

- 查看今日简报。
- 查看历史简报。
- 查看条目详情。
- 按分类、来源、关键词筛选条目。
- 查看信息库中的全量已采集内容。
- 配置“我的关注”规则。
- 保存站内搜索为关注规则。
- 对内容进行“多看类似”“少看类似”“屏蔽来源”等反馈。
- 查看原文链接。
- 保存基础用户偏好。

不允许：

- 管理信息源。
- 添加自定义外部 URL 信息源。
- 发起任意外部实时检索。
- 触发采集任务。
- 配置 LLM provider。
- 查看系统级错误日志。

### 3.2 管理员

管理员负责系统配置、数据源维护、任务运维和内容处理配置。

权限：

- 拥有普通用户全部权限。
- 管理 RSS/API source。
- 启用或禁用 source。
- 手动触发采集。
- 手动生成 digest。
- 查看任务日志和失败原因。
- 配置 LLM provider。
- 测试 LLM provider 可用性。
- 管理全局采集关键词和外部平台查询规则。
- 创建和管理用户账号。

### 3.3 系统任务

系统任务不是人类用户，但需要作为需求角色建模。

职责：

- 按计划采集数据。
- 标准化 raw item。
- 执行去重。
- 计算热度分。
- 调用 LLM 生成中文摘要。
- 生成每日 digest。
- 自动发布 digest 到 Web 看板。
- 记录任务状态和失败原因。

## 4. 业务流程

### 4.1 未登录用户查看今日简报

1. 用户打开 Web 站点。
2. 系统发现用户未登录。
3. 系统展示当天已发布的公开 digest。
4. 用户查看概览、重点条目卡片和原文链接。
5. 用户选择过去日期，系统展示该日期已发布的公开 digest；没有 digest 时展示空状态。
6. 用户点击登录后进入登录页。
7. 登录成功后进入今日简报工作区。

### 4.2 登录用户查看每日简报

1. 用户打开 Web 站点。
2. 系统检查登录状态。
3. 已登录用户进入今日简报工作区。
4. 用户查看今日重点、分类内容和条目摘要。
5. 用户点击条目，查看详情和原文链接。
6. 用户按来源、分类、关键词筛选内容。

### 4.3 管理员维护信息源

1. 管理员登录系统。
2. 进入来源管理页。
3. 新增、编辑、启用或禁用 source。
4. 系统校验 source 配置。
5. 管理员手动触发一次抓取验证。
6. 系统记录抓取状态和错误信息。

### 4.4 系统自动生成 digest

1. 定时任务触发采集。
2. 系统从所有启用 source 拉取 raw items。
3. 系统写入 raw payload。
4. 系统标准化 item。
5. 系统根据 URL、canonical URL、source external id 和标题 hash 去重。
6. 系统计算全局 score 并筛选候选内容。
7. 系统将相同事件的多来源内容聚合为 topic。
8. 系统调用 LLM provider 生成中文摘要、重要性说明和标签。
9. 系统生成当天 digest。
10. 系统自动发布 digest 到 Web 看板。
11. 系统记录 job run 状态。

### 4.5 用户配置我的关注

1. 用户登录系统。
2. 用户进入“我的关注”页面。
3. 用户配置关注关键词、排除关键词、关注分类、关注来源类型和屏蔽来源。
4. 用户保存配置。
5. 系统在该用户访问今日简报、历史简报和信息库时应用个性化规则。

### 4.6 用户站内搜索并保存为关注

1. 用户进入信息库。
2. 用户输入关键词，并选择分类、来源类型、时间范围等筛选条件。
3. 系统只检索已采集入库的内容。
4. 用户将当前搜索条件保存为关注规则。
5. 后续系统在“我的关注”视图中展示命中该规则的内容。

### 4.7 用户反馈偏好

1. 用户在今日简报、历史简报或信息库中查看内容。
2. 用户点击“多看类似”“少看类似”或“屏蔽来源”。
3. 系统记录用户反馈。
4. 后续排序时，系统对相似分类、标签、来源类型和关键词进行加权或降权。

详细图示见：[业务流程图](business-flow.md)。

## 5. 功能需求

### 5.1 公开今日简报

功能点：

- 未登录用户访问 `/` 或 `/today` 时可以查看当天已发布的 digest。
- 未登录用户可以通过首页日期筛选查看其他已发布日期的 digest。
- 展示简报日期、发布状态、概览和已发布条目卡片。
- 每条公开条目保留原文链接。
- 公开页面提供登录入口。
- 公开页面不加载收藏、关注、智能助手和管理接口。

验收标准：

- 未登录访问 `/` 返回公开今日简报，不跳转登录页。
- 未登录访问 `/today` 可以看到当天已发布内容。
- 首页选择过去日期后可以看到所选日期已发布内容。
- 今日 digest 未发布时展示公开空状态，不返回 401。
- 未登录用户不能通过公开页面执行收藏、反馈、信息库查询或管理操作。

### 5.2 用户认证

系统首期即支持多用户登录。

功能点：

- 用户账号只能由管理员创建。
- 用户登录。
- 用户退出。
- 获取当前登录用户信息。
- 区分普通用户和管理员角色。
- 未登录用户可以访问公开今日简报，但不能访问登录后工作区。

验收标准：

- 未登录访问受保护页面时跳转登录页。
- 登录成功后可进入今日简报页。
- 普通用户访问管理员接口时被拒绝。
- 系统不提供公开注册入口。
- 密码不明文存储。

### 5.3 今日简报

功能点：

- 展示当天 digest。
- 展示今日重点。
- 展示专题卡片，专题代表同一事件的多来源聚合。
- 按分类展示条目。
- 展示每条内容的标题、中文摘要、为什么重要、来源、发布时间、原文链接、分类和热度分。
- 支持“系统精选”和“我的关注”视图切换。
- 支持用户对内容反馈“多看类似”“少看类似”“屏蔽来源”。
- 无 digest 时显示空状态。

验收标准：

- 登录用户能看到今日 digest。
- digest 生成后自动出现在 Web 看板。
- 每条入选内容都有原文链接。
- 我的关注视图会应用用户关注、排除、屏蔽和反馈规则。

### 5.4 历史简报

功能点：

- 按日期查看历史 digest。
- 支持分类筛选。
- 支持打开历史条目详情。

验收标准：

- 用户能切换日期查看历史内容。
- 历史 digest 不因重新生成当天 digest 而丢失。

### 5.5 信息库

功能点：

- 查看所有已采集入库的信息。
- 包含入选 digest、未入选、低分、待摘要、摘要失败和重复聚合来源。
- 按来源筛选。
- 按分类筛选。
- 按处理状态筛选。
- 按关键词搜索。
- 按时间范围筛选。
- 按 score 和发布时间排序。
- 分页展示，支持每页 10、20、50、100 条。
- 支持从全局信息库悬浮聊天助手发起站内查询，并展示解析后的筛选条件。
- 自然语言聊天查询默认调用启用的 LLM Provider，通过 DeepAgents 受限 Agent 支持关键词扩展、时间表达和多条件意图理解。
- 后端必须先执行 `LibraryChatIntentClassifier`，范围外问题返回固定拒答，不调用 DeepAgents 和数据库检索。
- 支持用户级会话与消息历史落库，刷新后可恢复最近聊天记录。
- 展示动态数据概览：入库总数、已摘要数量、摘要覆盖率、来源数和平均分，默认折叠为数据洞察入口。
- 展示动态分布图表：入库趋势、来源类型、具体来源、分类和分数分桶。
- 支持点击来源类型、分类和分数分布项反向更新筛选条件。
- 将当前站内搜索条件保存为关注规则。

验收标准：

- 未进入 digest 的条目仍可查询。
- 摘要失败、采集失败、低分内容有明确状态。
- 信息库搜索和数据概览只查询系统已采集内容，不直接触发外部平台实时抓取。
- 自然语言检索无法解析时降级为关键词搜索，且不得触发外部实时检索。
- 代码编写、通用聊天、金融、天气、医疗、法律、外部实时搜索、提示词绕过和内容创作请求必须返回固定拒答。
- LLM 返回结果必须经过 JSON schema、枚举白名单、数值范围和权限校验；LLM 不得直接生成 SQL 或查询结果。
- Agent 只允许调用只读的 `search_library_database` 工具，工具内部复用现有信息库 service/repository。
- LLM 超时、不可用、返回非法 JSON 或校验失败时，接口返回 `mode=fallback` 并使用原句关键词检索。
- 用户点击数据洞察入口后，可以下拉展开完整数据大屏。
- 数据概览跟随当前检索条件动态刷新；新增来源或来源名称后无需改前端代码。
- 用户切换每页数量后，列表回到第 1 页并使用新的 `page_size` 重新请求。
- 保存搜索后，可以在“我的关注”中查看和管理该规则。

### 5.6 条目详情

功能点：

- 展示标题、来源、原文 URL、发布时间、抓取时间。
- 展示中文摘要、为什么重要、分类、标签、热度分。
- 展示原始摘要或正文片段。
- 展示相关条目或相同 topic 下的来源。
- 当内容属于某个 topic 时，展示专题摘要、相关来源和事件时间线。

验收标准：

- 用户可以从 digest、历史简报和信息库进入详情。
- 原文链接可打开。
- 处理失败时展示失败状态，不显示误导性摘要。

### 5.7 信息源管理

功能点：

- 查看 source 列表。
- 新增 RSS/API source。
- 编辑 source 名称、类型、URL、语言、权重和启用状态。
- 查看最近抓取时间。
- 查看最近错误。
- 手动触发单个 source 抓取。

首期 source 类型：

- RSS。
- Hacker News。
- GitHub。
- arXiv。
- Product Hunt。
- Hugging Face。

验收标准：

- 管理员能管理所有 source。
- 禁用 source 不再参与定时抓取。
- 单个 source 抓取失败不影响其他 source。

### 5.8 数据采集

功能点：

- 支持定时采集。
- 支持手动采集。
- 支持六类 source collector。
- 保存 raw payload。
- 保存 canonical URL、发布时间、抓取时间、来源类型。
- 记录采集任务状态。

验收标准：

- RSS、HN、GitHub、arXiv、Product Hunt、Hugging Face 都能成功抓取。
- 采集失败有错误日志。
- 重复抓取不会生成重复有效 item。

### 5.9 去重与评分

功能点：

- URL 去重。
- canonical URL 去重。
- source external id 去重。
- 标题归一化 hash 去重。
- 基于来源权重、新鲜度、社区热度、关键词相关性计算 score。
- 将相同事件的多来源内容聚合为 topic。
- 在全局 score 基础上，根据用户关注规则计算个性化 user score。

验收标准：

- 同一 URL 不重复出现在 digest。
- 列表默认按 score 降序。
- score 主要来源可解释。
- 用户关注关键词、关注分类和反馈只影响该用户排序或默认筛选，不改变全局 score。

### 5.10 我的关注

功能点：

- 用户配置关注关键词。
- 用户配置排除关键词。
- 用户配置关注分类。
- 用户配置关注来源类型。
- 用户屏蔽指定来源。
- 用户将信息库中的站内搜索条件保存为关注规则。
- 用户查看和管理反馈记录，包括“多看类似”“少看类似”“屏蔽来源”。

规则说明：

- 关注关键词用于软加权，不作为唯一展示条件。
- 关注分类用于我的关注视图默认筛选，并参与轻量排序加权。
- 关注来源类型用于默认筛选。
- 关闭来源类型用于硬过滤。
- 排除关键词用于硬过滤。
- 屏蔽来源用于硬过滤。
- 多看类似用于提升相似分类、标签、来源类型和关键词的个性化权重。
- 少看类似用于降低相似分类、标签、来源类型和关键词的个性化权重。

验收标准：

- 用户保存关注规则后，“我的关注”视图会优先展示相关内容。
- 排除关键词和屏蔽来源会从该用户个性化视图中隐藏对应内容。
- 用户偏好只影响当前用户，不影响全局 digest 和其他用户。
- 普通用户不能通过“我的关注”添加外部 URL 信息源。

### 5.11 我的收藏

功能点：

- 用户收藏或取消收藏信息条目。
- 用户创建、重命名、删除单层收藏目录。
- 用户在根目录、自建目录和全部收藏之间切换。
- 支持按目录搜索、分类、来源、收藏时间、发布时间和分数筛选排序。
- 收藏列表和条目详情共享收藏状态。

验收标准：

- 未登录用户不能查看或操作收藏。
- 收藏与目录按用户隔离，管理员也不能读取或修改其他用户收藏。
- 删除目录后目录内收藏自动回到根目录，不删除原条目。
- 同一用户不能重复收藏同一条目。


### 5.12 LLM 中文摘要

功能点：

- 对高分候选条目生成中文摘要。
- 生成“为什么重要”。
- 生成标签，分类由信息源规则确定。
- 输出置信度。
- 记录 provider、模型名、prompt 版本和调用状态。
- 摘要失败时使用原始摘要兜底并标记状态。

验收标准：

- 进入 digest 的 item 必须有中文摘要或明确兜底摘要。
- 摘要模块只依赖统一 provider 接口。
- 更换 provider 不需要修改业务摘要代码。

### 5.13 LLM Provider 管理

功能点：

- 配置多个 LLM provider。
- 设置默认 provider。
- 配置模型名、base URL、超时时间、重试次数和启用状态。
- 支持 OpenAI-compatible API。
- 信息库智能聊天查询和中文摘要共用 Provider 抽象；自然语言查询使用默认启用 Provider。
- 测试 provider 可用性。

验收标准：

- 管理员可查看和测试 provider。
- provider key 不暴露给前端。
- provider 调用失败有日志。

### 5.14 任务状态与日志

功能点：

- 查看采集、处理、摘要、digest 生成和发布任务。
- 查看任务开始时间、结束时间、状态、耗时和错误信息。
- 支持管理员手动重跑。
- 支持管理员配置 digest 自动生成时间，默认北京时间每天 08:00。

验收标准：

- 失败任务可追溯。
- 摘要失败不会阻塞整个 digest。
- 单个 source 失败不会阻塞其他 source。

### 5.15 用户管理

功能点：

- 管理员查看用户列表。
- 管理员创建用户账号。
- 管理员设置用户角色。
- 管理员启用或禁用用户。
- 管理员重置用户密码。
- 系统不提供公开注册入口。

验收标准：

- 只有管理员可以创建用户。
- 新用户创建后可使用管理员提供的账号密码登录。
- 被禁用用户不能登录系统。
- 普通用户不能访问用户管理接口或页面。

## 6. 非功能需求

### 6.1 性能

- 首页简报数据响应小于 1 秒。
- 信息库列表数据响应小于 2 秒。
- 单次采集任务在 5-10 分钟内完成。
- 每日 digest 生成在 5 分钟内完成。

### 6.2 安全

- 外公网部署必须启用登录认证。
- 用户密码必须加密存储。
- 管理接口必须进行权限校验。
- API key 和 LLM provider key 不提交到仓库。
- provider key 不暴露到浏览器。
- 外部 URL 抓取限制超时、重定向次数和响应大小。
- 前端展示外部内容时防止 XSS。

### 6.3 稳定性

- 单个 source 失败不影响整体任务。
- 单个 LLM provider 失败可标记失败或回退备用 provider。
- 定时任务需要记录状态。
- 任务失败需要可重试。
- 系统应能展示空状态、加载状态和错误状态。

### 6.4 可维护性

- 不同 collector 实现统一接口。
- LLM provider 实现统一接口。
- Prompt 版本化。
- 评分规则集中配置。
- 后端 API、采集任务和前端页面解耦。
- 前端内容区使用统一 UI primitives，避免页面级重复实现表单、卡片、提示、指标和表格样式。

### 6.5 可追溯性

- 保留 raw payload。
- 保留原文 URL。
- 保留 source id。
- 保留摘要模型和 prompt 版本。
- 保留处理时间、任务状态和错误信息。

### 6.6 兼容性

- 首期 Web 看板支持主流桌面浏览器。
- 前端布局应适配常见笔记本屏幕和宽屏显示器。
- 桌面端侧边栏支持展开/折叠；移动端侧边栏应以抽屉方式打开。
- 主内容区应在桌面端保持信息密度，在移动端改为单列卡片布局。
- 后端通过 Docker Compose 支持本地和外公网服务器部署。
- 外部 API token 缺失时，对应 source 应明确显示未配置状态。
- 外部 API token 允许管理员后台录入，后端加密保存。

### 7.1 业务数据对象

系统首期需要管理以下业务数据对象，详细表结构、字段类型、索引和关联关系在数据库设计阶段单独输出。

- User。
- AuthSession。
- Source。
- RawItem。
- Item。
- Topic。
- Digest。
- DigestItem。
- JobRun。
- LLMProvider。
- UserPreference。
- SavedSearch。
- UserFeedback。

### 7.2 内容处理状态

信息内容需要具备可追踪的处理状态：

- `collected`。
- `normalized`。
- `deduped`。
- `ranked`。
- `summarized`。
- `selected`。
- `failed`。

### 7.3 个性化规则数据

系统需要保存用户级个性化规则：

- 关注关键词。
- 排除关键词。
- 关注分类。
- 关注来源类型。
- 屏蔽来源。

## 8. 外部接口与集成需求

本阶段只描述业务集成范围，不定义具体 REST API 路径、请求响应结构或数据库表结构。详细接口设计在后续《接口设计说明书》中输出。

系统首期需要支持以下集成能力：

- 用户认证能力：登录、退出、当前用户识别和角色校验。
- 用户管理能力：管理员创建用户、启用/禁用用户、设置角色和重置密码。
- 内容查询能力：查询公开今日简报、登录后今日简报、历史简报、信息库、详情和个性化视图。
- 采集管理能力：管理员管理全局 source、配置外部平台查询规则、手动触发采集。
- 任务管理能力：管理员查看采集、处理、摘要、digest 生成和发布状态。
- LLM 管理能力：管理员配置、启用、停用和测试多厂商 provider。
- 外部数据源集成：RSS、Hacker News、GitHub、arXiv、Product Hunt、Hugging Face。

## 9. MVP 边界

### 9.1 MVP 必须包含

- 多用户登录。
- 管理员创建用户。
- 普通用户和管理员角色。
- 外公网部署所需基础安全配置。
- 六类采集器：RSS、HN、GitHub、arXiv、Product Hunt、Hugging Face。
- 原始条目入库。
- 去重和评分。
- 多厂商 LLM provider 抽象。
- 中文摘要。
- 自动生成和发布 digest。
- 公开今日简报页面。
- 登录后今日简报页面。
- 历史简报页面。
- 信息库和详情抽屉。
- LLM 驱动的信息库智能聊天助手。

### 9.2 MVP 暂不包含

- 付费订阅系统。
- 原生移动端。
- 浏览器插件。
- 音频日报。
- 高级 embedding 聚类。

## 10. 验收标准

- 未登录用户可以访问公开今日简报。
- 未登录用户不能访问登录后工作区。
- 普通用户不能访问管理功能。
- 管理员可以管理 source、job、用户和 LLM provider。
- 六类 source 均可执行采集并记录状态。
- 每日 digest 自动生成并发布到 Web 看板。
- digest 条目包含中文摘要、为什么重要、来源、分类、score 和原文链接。
- 重复 URL 不会在 digest 中重复出现。
- 摘要失败不会阻塞整个 digest。
- 我的关注规则会影响当前用户排序和默认筛选，但不影响其他用户。
- 普通用户不能添加外部 URL 信息源或触发任意外部实时检索。
- provider key 不暴露到前端。
- README 提供本地启动和外公网部署说明。

## 11. 已确认默认值

- 首个管理员账号通过一次性 `create-admin` 命令创建。
- 首批默认 source 每类预置 1-3 个最小可用配置，后续管理员可在后台调整。
- `raw_items`、`llm_call_logs`、`job_runs` 默认保留 180 天。
- `items`、`topics`、`digests` 默认长期保留。
- PostgreSQL 每日备份一次，默认保留 14 天。
