## 1. 产品概述

### 1.1 产品定位

Daily News 是一个面向外公网部署的多用户 AI 情报聚合 Web 看板。系统自动采集 RSS、Hacker News、GitHub、arXiv、Product Hunt、Hugging Face 等来源中的 AI 相关信息，经过去重、轻量 topic 聚合、评分和 LLM 中文摘要后，自动生成每日简报。

产品首期不做推送渠道，不开放公开注册，不允许普通用户添加外部 URL 信息源。普通用户通过“我的关注”配置个性化规则，影响自己的看板排序和默认筛选。

### 1.2 核心价值

- 帮助用户快速了解当天 AI 热点。
- 把分散来源统一到一个可检索 Web 看板。
- 通过中文摘要和“为什么重要”降低理解成本。
- 通过信息库沉淀全量可搜索内容。
- 通过我的关注提供可解释的个性化排序。
- 通过管理员后台保障来源、任务、用户和 LLM 配置可维护。

### 1.3 产品原则

- 信息优先：页面以扫读、筛选和追溯为主，不做营销型首页。
- 来源可追溯：每条摘要必须能回到原文。
- 个性化可解释：先做规则型关注、屏蔽和反馈，不做黑盒推荐。
- 权限收紧：外公网部署下，账号只能由管理员创建。
- 采集受控：普通用户不能发起任意外部实时检索。

## 4. 信息架构

### 4.1 普通用户导航

### 4.2 管理员导航

- 来源管理。

### 4.3 全局导航体验

- 侧边栏按 shadcn/ui Sidebar 风格组织为 Header、分组导航和 Footer。
- 桌面端支持展开/折叠，折叠后保留图标导航和当前页高亮。
- 移动端通过顶部菜单按钮打开抽屉式侧边栏。
- 底部用户区展示当前用户和角色，顶部栏保留退出登录。

### 4.4 主内容区体验

- 主内容区统一使用 PageHeader 承载页面标题、说明和页面级操作。
- 筛选、设置、说明和高级操作统一使用 SurfaceCard。
- 关键数字统一使用 MetricCard，避免每页重复实现指标样式。
- 成功、错误、提示统一使用 Notice。
- 数据表统一使用 TableCard 包裹；任务日志使用 TanStack Table 提供排序能力。
- 内容流统一使用卡片列表，卡片内固定展示标题、摘要、来源、分类、分数和原文入口。

| 页面 | 职责 | 不负责 |

| 任务日志 | 查看任务状态和失败原因 | 内容消费 |

### 5.4 信息库

目标：

- 作为系统已采集内容的全量搜索入口。

核心组件：

- 关键词搜索框。
- 来源筛选。
- 来源类型筛选。
- 分类筛选。
- 状态筛选。
- 时间范围筛选。
- 排序。
- 保存搜索按钮。
- 动态数据概览：入库总数、已摘要数量、摘要覆盖率、来源数、平均分，默认以折叠洞察条展示。
- 动态图表：入库趋势、来源类型分布、具体来源 Top、分类分布、分数分布，前端以交互式图表呈现。
- 分页列表，支持每页 10、20、50、100 条。

内容范围：

- 入选 digest 的内容。
- 未入选 digest 的内容。
- 低分内容。
- 待摘要内容。
- 摘要失败内容。
- 被聚合到 topic 下的相关来源。

交互规则：

- 信息库只搜索已采集入库内容。
- 信息库不直接触发外部平台实时检索。
- 数据概览跟随当前检索条件和时间窗口动态刷新。
- 用户点击数据洞察入口后，下拉展开完整数据大屏。
- 图表维度由后端返回，新增采集来源后自动展示。
- 用户点击来源类型、分类或分数分布项时，系统反向写入筛选条件并重新检索。
- 用户调整每页数量时，列表回到第 1 页并按新的 page_size 重新请求。
- 用户可将当前搜索条件保存为我的关注规则。
- 管理员可对单条内容重新摘要。
- 页面采用 PageHeader、SurfaceCard、ECharts 数据大屏、结果卡片列表、详情面板和 PaginationBar 组合。

- 关注分类。
- 关注来源类型。
- 屏蔽来源。
- 保存的搜索。
- 反馈记录。
- 保存按钮。

规则说明：

- 关注关键词：软加权。
- 排除关键词：硬过滤。
- 关注分类：我的关注视图默认筛选，并作为轻量排序加权。

## 7. 个性化策略

### 7.1 排序原则

系统先计算全局 score，再根据用户规则生成 user score。

```text
user_score =
  global_score
  + keyword_boost
  + category_boost
  + more_like_this_boost
  - less_like_this_penalty
```

### 7.2 硬过滤

以下规则直接隐藏内容，作用范围仅限当前用户：

- 排除关键词。
- 屏蔽来源。
- 用户关闭的来源类型。

### 7.3 软加权

以下规则只影响排序，不直接排除内容：

- 关注关键词。
- 关注分类。
- 多看类似。
- 少看类似。

### 7.4 默认筛选

以下规则用于“我的关注”视图的默认查询条件，用户可以在当前页面临时清除筛选，但不会改变已保存规则：

- 关注分类。
- 关注来源类型。
- 保存搜索中的来源、分类、状态和时间范围。

### 7.5 规则执行顺序

我的关注视图按以下顺序处理：

1. 读取当前页面范围，如今日 digest、历史 digest 或信息库搜索结果。
2. 应用硬过滤，移除排除关键词、屏蔽来源和关闭来源类型命中的内容。
3. 应用默认筛选，限制关注分类、关注来源类型和保存搜索条件。
4. 计算 user score，叠加关注关键词、关注分类和反馈权重。
5. 按 user score、发布时间和全局 score 排序后展示。

## 8. 用户体验要求

- 首页默认展示今日简报，不做营销页。
- 信息卡片要支持快速扫读，不堆长文本。
- 每条内容都应能打开详情和原文。
- 筛选结果为空时要明确说明是否只搜索站内内容。
- 管理员操作必须有成功/失败反馈。
- 任务失败要显示可理解的错误摘要。
- LLM 摘要失败时不能伪装成成功摘要。
- 信息库智能聊天必须展示意图门控状态、LLM 解析出的查询说明、筛选条件和置信度；LLM 不可用时明确展示降级状态。

- 多看类似/少看类似/屏蔽来源点击次数。
- 管理员手动重跑任务次数。
- source 抓取成功率。

## 11. 已确认默认值

- 首个管理员账号通过一次性 `create-admin` 命令创建。
- 首批默认 source 每类预置 1-3 个最小可用配置，管理员可在来源管理页继续调整。
- `raw_items`、`llm_call_logs`、`job_runs` 默认保留 180 天。
- `items`、`topics`、`digests` 默认长期保留。
- PostgreSQL 每日备份一次，默认保留 14 天。
